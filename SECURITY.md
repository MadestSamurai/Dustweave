# Security reporting / 安全问题反馈

账号会话、登录信息和本地连接涉及敏感数据。不要把凭据、完整用户目录或可直接利用的安全细节贴到公开 Issue、PR 或日志附件。

如果仓库 **Security → Report a vulnerability** 入口可用，请使用私密报告。当前私有预览未配置公开的私密漏洞报告入口或专用安全邮箱；已有协作者可联系维护者。没有私下联系渠道时，先提交只写“希望私下报告安全问题”的 Issue，由维护者安排后续渠道，不附漏洞细节。

普通运行错误请使用错误报告模板。安全修复会面向正在维护的版本处理，不承诺所有旧版都提供补丁或固定响应期限。

Account sessions, login data and local connection details can be sensitive. Never post credentials, complete user-data folders or actionable vulnerability details in public issues, pull requests or diagnostic attachments.

Use **Security → Report a vulnerability** if GitHub makes it available. This private preview currently has no configured public private-reporting entry or dedicated security email. Existing collaborators may contact the maintainer; otherwise open a minimal issue requesting a private channel, with no vulnerability details, and wait for the maintainer to arrange one.

Use the bug-report template for ordinary failures. Security fixes target maintained versions; support for every older release or a fixed response deadline is not guaranteed.
