# 工具界面 UX 规范

适用于 Dustweave 内置的全部工具窗口（装备、钓鱼、领地、连连看、音游、爬塔、秘境、恶魔猎人、宅邸、潘多拉、无限抽）以及宿主自有的工具型对话框（料理与售卖清单等）。本规范在 `DESIGN.md`「Tool windows」之上细化；两者冲突时以 `DESIGN.md` 的硬性约束（标题区、主题资源、三语、恢复性）为准，并在此同步修订。

## 1. 目标与判断标准

每个工具窗口都要让玩家在三秒内回答三个问题：

1. **现在是什么状态？**（未连接 / 准备中 / 就绪 / 运行中 / 已停止 / 需要处理 / 已完成）
2. **下一步我该做什么？**（一句具体的话，或一个可点的按钮）
3. **它会做什么、不会做什么？**（只在做决定的地方说明一次）

评审时按「易用 → 直观 → 美观」排序：先保证不会误操作、出错能恢复，再保证一眼能懂，最后才是视觉精修。

## 2. 窗口骨架

所有工具使用同一骨架，从上到下：

| 区域 | 内容 | 规则 |
|---|---|---|
| 标题区（宿主提供） | 26 DIP 标题 + 最小化/最大化/关闭 | 工具内不再重复标题或宣传语。 |
| 状态带 | 状态标题、一句下一步、可选实时指标 | 见 §3。永远位于正文最上方、不随设置滚走。 |
| 主体 | 板面型或表单型（见 §5、§6） | 只有主体滚动；24 DIP 左右内边距。 |
| 底部操作栏 | 左：连接游戏；中：运行简况；右：次要操作、停止、主操作 | 见 §4。始终可见，与内容之间一条细分隔线。 |

- 不在整页外面套卡片，不嵌套卡片。允许的卡片只有：状态带（Surface 底、8 DIP 圆角）和板面画布。
- 分节使用「14 DIP 半粗体节标题（ToolSectionTitle）+ 细分隔线」，不用卡片分节。
- 窗口最小尺寸下（各工具现有 MinWidth/MinHeight）主操作、状态带、板面必须完整可见；三语都不出现横向滚动或文字裁切。

## 3. 状态带

一个组件，三层信息，按需出现：

1. **状态标题**（16 DIP 半粗体，前置 16 DIP 状态图标）：短语，不超过 10 个汉字或 4 个英文词，例如「等待连接游戏」「正在钓鱼」「需要处理」。
2. **下一步 / 说明**（13 DIP，MutedInk，一句话）：告诉用户此刻该做什么，或运行中正在做什么。错误状态写原因和恢复办法，不写笼统安慰语。
3. **实时指标**（可选，横向排列）：标签 12 DIP MutedInk，数值 20 DIP。**没有实时数据前整行隐藏**，不显示「—」「尚未读取」占位。

状态与颜色、图标一一对应（图标取自 `Icons.xaml`，颜色只作辅助，文字必须能独立表达状态）：

| 状态 | 图标 | 强调色 |
|---|---|---|
| 未连接 / 等待 | Link | MutedInk |
| 准备中 / 读取中 | Clock | MutedInk |
| 就绪 | Check | Success |
| 运行中 | Play | Primary |
| 已停止 / 暂停 | Pause | MutedInk |
| 需要处理 | Warning | Warning（WarningSoft 底） |
| 失败 | Warning | Error（ErrorSoft 底） |
| 已完成 | Check | Success |

## 4. 底部操作栏

- 顺序固定：`[连接游戏]   运行简况…   [次要操作] [停止] [主操作]`。连接游戏只在需要连接或重连时可用；自动连接的工具在已连接时把它隐藏。
- 主操作使用 PrimaryButton，全窗口只有这一个实心强调按钮。
- **禁用必须有原因**：主操作不可用时，在状态带下一步或运行简况中说明缺什么（如「先连接游戏」「先选择关卡」），并把同一句写进按钮的 ToolTip（`ToolTipService.ShowOnDisabled=True`）。
- 停止与主操作位置固定，不因状态变化而移动；运行中主操作禁用，停止可用。
- 运行简况一行，超长截断并在 ToolTip 显示全文；错误用 Error 色，其他用 MutedInk。

## 5. 表单型主体

- **标签在上，控件在下**；同一节内左侧对齐。复选框与单选框的文字就是标签，不再另加。
- **数字输入**：固定宽度 120 DIP（大数值 160），单位放在框外右侧（`ms`、`%`、`次`），不写进标签括号。范围写在 ToolTip 或框下一行帮助里，不同时出现。
- **帮助文字**：每个设置最多一行，放在控件下方 12–13 DIP MutedInk；超过一行改为节标题旁的 ⓘ ToolTip。
- **从属选项**：缩进 24 DIP；父选项关闭时隐藏（不是禁用），避免一屏全是灰色控件。
- **即时生效**：设置输入有效即保存，不提供单独的「应用」按钮；需要下一局或下一曲才生效的，在帮助文字里写「下一局生效」。
- **校验**：输入时校验，就地红框 + 框下一行原因；主操作同时禁用并在运行简况说明。空值有合理默认含义时（如「留空表示不限」）用框内占位文字说明。
- **选项组**：同权重的 2–5 个互斥选项用分段按钮或单选组横排；超过 5 个用下拉框。

## 6. 板面型主体

- 板面在左、控制栏在右（宽 320–360 DIP）；窗口变窄时控制栏移到板面下方。
- 板面空状态居中显示两行：做什么（「进入小游戏后显示盘面」）+ 怎么做（「在游戏中打开 … 后点击连接游戏」）。
- 图例使用色块 + 文字，置于板面左下，色值来自主题资源并提供高对比回退。
- 板面上的实时信息（得分、生命、连锁）放进状态带的实时指标，不在控制栏重复。

## 7. 列表与选择

- **两栏挑选**（目录 → 已选/顺序）：不用中间穿梭按钮栏；目录行末「＋」、双击、回车、拖动加入；已选行首序号，行末 ↑ ↓ ×，双击或 Delete 移除，Alt+↑/↓ 或拖动排序并显示插入线。两侧都有就地空状态。参考 `DailyCookingWindow`。
- **勾选列表**：工具行包含搜索（占位文字）、「只看已勾选」、计数、清除；勾选不触发重新排序；没有业务含义的整行选中不加底色。
- 列表行高 40 DIP，表头 SurfaceMuted，横向细分隔线，无竖线、无斑马纹。长文本单行截断并提供 ToolTip；窄宽度时把次要列折到名称下方的第二行，而不是把名称挤成「…」。

## 8. 文案

- 一个概念一个词：连接游戏、开始、停止、重新连接、读取、刷新库存、保存。按钮文字与帮助里引用的按钮名称完全一致。
- 不写重复标题的介绍语、默认值提醒和实现细节（帧、Hook、IPC）。
- 句子以「做什么」开头：「进入领地后点击连接游戏」，而不是「若您已进入领地，则可以…」。
- 数字与单位之间留半角空格（`1000 ms`、`90 %` 除外按中文习惯 `90%`）；中文全角标点，英文半角。
- 工具内中文写在 XAML/代码中，英文写进该工具 `localization/en-US.json`，繁体由宿主 `HostedTraditionalText` 生成；新句子必须同时补英文。英文预留 30–50% 长度。

## 9. 视觉基准

- 间距：4 / 8 / 12 / 16 / 24 DIP；节与节之间 24，标签与控件 6，控件与帮助 4。
- 字号：12（指标标签、表头）/ 13（帮助、说明）/ 14（正文、控件）/ 16（状态标题、节标题可选）/ 20（实时数值）/ 26（窗口标题）。
- 控件高度 36；圆角：按钮与输入框 8、下拉框 6、卡片 8–10。
- 颜色只使用主题资源键（AppBackground、Surface、SurfaceMuted、Line、LineStrong、Ink、MutedInk、Primary、PrimarySoft、Success、Warning(Soft)、Error(Soft)、Focus）。工具不得写死颜色；板面分类色需提供明暗两套与高对比回退。
- 图标统一 16 单位画布、1.5 圆头线宽（`LineIcon` 样式）。

## 10. 交互与可访问性

- 全部操作可用键盘完成；Tab 顺序与视觉顺序一致；焦点可见且不改变布局。
- 每个图标按钮有本地化 AutomationName 与 ToolTip；状态变化不只靠颜色。
- Esc 留给下拉框、编辑框与板面选择，不关闭工具窗口。
- 运行中禁止修改会影响当前执行的设置时，控件禁用并在帮助中说明「停止后可修改」；其余设置保持可改。
- 不引入装饰性动画；进度条与计数只反映真实确认的进展。

## 11. 验收清单（每个工具）

- [ ] 骨架：状态带 / 主体 / 底部操作栏顺序与位置符合 §2、§4；无嵌套卡片、无重复标题。
- [ ] 状态带：未连接、准备、就绪、运行、需要处理五种状态文案与图标正确；无实时数据时不显示占位指标。
- [ ] 主操作禁用时有可见原因（状态带或运行简况 + ToolTip）。
- [ ] 表单：标签、单位、帮助、从属缩进、即时生效、就地校验符合 §5。
- [ ] 板面/列表：空状态、图例、选择交互符合 §6、§7。
- [ ] 文案：术语一致，新句子已补英文，无实现细节。
- [ ] 三语 × 明暗 × 最小/常规尺寸截图检查（`DUSTWEAVE_UI_SMOKE_SCOPE=tool-preparation`），无裁切、无横向滚动。
- [ ] 后台类型检查通过；工具原有自检与回归分组通过。
