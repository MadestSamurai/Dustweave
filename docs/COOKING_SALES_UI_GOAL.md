# 料理与售卖清单界面 Goal

2026-11-07 启动。范围：日常设置 → 交易 → 「料理与售卖清单」窗口（`src/Desktop/DailyCookingWindow.cs`、`src/Desktop/DailySalePanel.cs`）及其三语文案、隔离 UI 自检。只改界面与交互，不改执行逻辑和保存格式。

## 目标

用户打开窗口后，不读说明也能知道：三页按「采购 → 制作 → 出售」先后执行；哪些料理会按什么顺序制作；哪些物品会在 120% 报价时卖、各保留多少；做出来的料理会不会被卖掉。

## 已确定

- 保存格式不变：`CookingRecipes` 仍为有序配方 ID，`Sales` 仍为 `DailySalePreference`（未勾选但保留量大于 0 的条目照旧保存）。核心执行、过滤不改变已存选择的行为保持不变。
- 料理顺序页取消中间穿梭栏，改为两栏：目录行末「＋」、双击或回车加入，可拖入指定位置；顺序行首显示序号，行末 ↑ ↓ × 图标按钮，双击或 Delete 移除，Alt+↑/↓ 或拖动排序。两侧空列表、无搜索结果有就地说明。
- 搜索框统一使用框内占位文字（14 DIP，不另设标签）。
- 售卖页：一行要点说明，细节放入「保留量」列提示；工具行含搜索、「只看已勾选」、已勾选计数和清除勾选；打开时已勾选物品排在前面，勾选过程中不跳行；未勾选时保留量不可编辑；保留量即时校验并就地标红，留空视为 0；去掉无意义的整行选中底色，空格切换当前行。
- 三页互相可见：标签显示数量；售卖料理页标出「会制作」，料理顺序页标出「会出售」；底部状态栏始终显示三页汇总。
- 主题资源、控件几何、三语同步按 `docs/DESIGN.md`；新增文案使用稳定键，旧键与 `legacy-inputs.json` 映射保留。
