# 1.4.19 legacy publisher follow-up

The application release is built from tag `v1.4.19` (`b7c441f`). This separate
server-only change does not replace its already tested or published packages.

The legacy repair publisher verified and persisted every origin block, then
spent the entire 15-minute publication deadline probing optional mirror copies.
Two operations failed before exposing the signed repair inventories. The capable
feed remained on 1.4.18. The second operation reused all uploaded blocks and still
timed out, distinguishing the optional probe problem from upload duration.

Optional repair-mirror verification now has a **30-second total budget**. A probe
timeout leaves verified origin files usable; only fully downloaded and hashed
mirror bodies receive redirect markers. Mandatory origin hashes, both signed
inventories, replay/expiry checks, current-feed checks and publication locking
are unchanged. Parent cancellation still fails the operation.

The server self-test passed **154 checks**, including valid mirror content,
same-length corruption and an indefinitely stalled response. Those cases verify
both signed manifests, durable completion, unchanged feed bytes and redirect
markers only for matching content. Source validation and the self-contained
Linux publisher build passed.

The administrator installer is prepared under the maintenance worktree's
`artifacts/deployments/1.4.19/install-publisher-origin-fix.sh`. It checks the
payload hash, acquires both v2 publication locks, keeps a rollback executable,
runs the publisher checks, replaces only the v2 publisher and verifies that all
three channels' feeds and the v2 configuration remain byte-identical. It does
not change nginx, application packages or the 1.5 publisher.

Deployment is pending administrator access. Failed operations and the prepared
installer are retained in `artifacts/deployments/1.4.19`.
