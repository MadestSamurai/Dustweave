# Dustweave 1.4.12

自动钓鱼和领地自动化完成迁入，所有工具现在都在 Dustweave 的 `src` 目录维护，随本体更新。

- 钓鱼和领地保留独立窗口，打开后先显示加载进度，再准备连接。可取消、重试；准备期间与日常、其他工具互斥，连接完成后不会自行开启自动化。
- 两个工具采用织尘的控件、深浅主题和全局语言。钓鱼的开始／停止按钮固定在底部，领地布局窗口也使用统一弹窗样式。
- 自动沿用有效的旧设置；新日志纳入织尘诊断导出与清理。保留种植、料理和售卖的未确认记录，不因目录迁移丢失状态。
- 修复周收集按固定吸收次数估算的问题，改为读取当前账号已学习天赋的实际次数；次数不足时不会自动转成步行收集。
- 多账号进度改用逐项时间线，在账号下显示当前环节、细分步骤和完成时刻。仅执行一个账号时，手动、定时及启动后执行均进入单账号视图。
- “今日任务”的预设区保留一个保存入口，菜单保留覆盖、重命名和删除。
- 更新中英文 README、模块链接和更新支持说明。原钓鱼、领地仓库停止独立维护。

本次不改变钓鱼的保留／出售规则，或领地的种植、采集和售卖策略。首次连接仍需等待当前客户端组件准备完成。

## English

Fishing and Territory are now owned Dustweave modules. All tools are maintained under `src` and ship with the host.

- Their separate windows appear before connection preparation, with progress, cancellation and retry. Preparation shares the automation lock; readiness never starts automation.
- Both tools follow the host theme, controls and global language. Fishing actions remain visible while scrolling, and territory layouts use the shared dialog shell.
- Valid existing settings are imported once. New logs join the host's export and retention; pending planting, cooking and sale journals remain intact.
- Weekly collection uses the current account's learned talent allowances rather than assuming a fixed number of absorption uses. Exhaustion does not silently enable walking collection.
- Multi-account runs use per-account task timelines. A single selected account, including scheduled or startup execution, uses the single-account view.
- Removes the duplicate preset-save action and refreshes both READMEs, source links and update guidance.

Fishing retention and territory automation policies remain unchanged. The original repositories are retained as archived historical sources.
