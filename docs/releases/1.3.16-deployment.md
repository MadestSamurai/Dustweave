## Source and validation

- Tag `v1.3.16`: `db8cc2af02b0de24aad9cc4e7f53e80c99cf1ea2`. [Release notes](1.3.16.md) cover actionable task explanations, merged per-map collection/theft progress, the integrated Apostle Defense window and shared tool connection ownership. The defense planner and strategy are unchanged.
- Full synthetic regression: **4,534 checks in 100 groups**. Both editions passed packaged UI checks, including task explanations in three languages/two themes, tower-window loading/cancellation/closing, and **89 tool-contention checks per edition**. Current-client observation configuration checks passed for all 11 configurations; the unified suite passed all 15 components. Packaged native command checks passed all 606 checks.
- [Source CI](https://github.com/MadestSamurai/Dustweave/actions/runs/38748765614) and [release workflow](https://github.com/MadestSamurai/Dustweave/actions/runs/38752200161) passed. GitHub Actions verified the source tag, candidate identities, hashes and distribution boundary before publishing the normal release.
- The first Portable tool-UI run failed the infinite-gacha notification assertion `test during running preserves run`. The same unchanged package passed all 47 checks in two fresh isolated runs and again at the resumed packaging checkpoint. No production fix was inferred from this non-reproduced assertion. The original failure remains in `Portable-checks/tools/infinite-gacha-first-failure`; source equality was checked before reusing completed tests and resuming the remaining package checks. Lite ran its normal gates. `release-provenance.json` records this resume.
- The actual **1.3.15 updater** passed Lite/Portable upgrades, startup-failure rollback and interrupted-bootstrap recovery, with installed file hashes and preserved account/plugin sentinels checked. In addition to the standard harness, the final publishing evidence uses the exact release patch files. The additional harness initially required a PowerShell-to-.NET descriptor conversion fix; its failed evidence is preserved, and the corrected harness passed all cases. This did not change application code or release bytes.
- Tests used isolated user data, did not register scheduled tasks and did not connect to or operate the game. Interruption was injected, not a physical power cut. These checks do not establish live gameplay success rates.
