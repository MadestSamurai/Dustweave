# AIO mirror preparation recovery · 2026-11-01

Status: production mirror delivery restored and verified; temporary access revoked.
This server-only maintenance does not rebuild or replace the released 1.5.10
application, its archives, differential files or signed feed.

## Failure and correction

After the 1.5.10 publication, the origin reported a missing mirror verification
receipt. All 20 objects had passed local complete public-download verification,
but origin-side preparation had not completed. Its health-only timer repeatedly
reported the missing receipt without restarting preparation, and replaced the
earlier health error. The original origin-side failure therefore cannot be
identified from the retained status alone. Before this publication, the 1.5.9
channel also reported origin fallback with a canceled request.

The publisher now saves per-file progress bound to the exact signed feed and
delivery endpoint, retries transient failures, and resumes preparation from its
existing timer. The four-minute maintenance budget is shorter than the new
five-minute service timeout. The publication lock prevents competing work; an
occupied lock leaves existing routes untouched. Complete matching objects and
a fresh health check remain mandatory before enabling redirects. Content
corruption, mismatched lengths, arbitrary redirects and stale feed checkpoints
do not bypass verification. A changed local origin file is rehashed and rejected.

First failure, latest failure, affected file and recovery time are preserved in
separate diagnostics. Signed publication remains independently usable via origin
fallback during a network outage. Normal healthy checks do not download all bodies.

## Validation and installation

Windows and the self-contained Linux executable each passed **169 publisher
checks**. Added scenarios cover bounded retries, interrupted preparation, durable
progress, timer recovery, original-error retention, exact checkpoint binding,
corrupt content, changed local files, concurrent publication and feed changes.

A network-disabled Linux container verified four installation cases: successful
replacement with unchanged feeds/configuration, rollback after an injected service
reload failure, invalid payload hash rejection, and refusal while publication is
locked. These tests operated on an isolated filesystem; no production service
or game was touched.

Installer: `scripts/upgrade-update-aio-mirror.sh`. It checks the exact executable
and feed hashes, backs up the existing publisher and service override, installs
only the AIO executable and timeout override, verifies unchanged signed feeds and
nginx, then starts a bounded background recovery attempt. Temporary network failure
keeps the recovery-capable executable installed and origin delivery available.
