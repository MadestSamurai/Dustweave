## Delivered behavior and validation

The release adapts connection and daily flows to the current game client, repairs
ordinary and isolated startup handling, synchronizes isolated game resources,
and improves prompt cancellation when the game exits. Event attempts finish
normally when free attempts are exhausted; Bingo handling follows the available
mechanics rather than activity titles. Trading refreshes current compatible
tables. Update restart drains startup maintenance and acknowledges the actual
new application before starting background work. Experimental fast travel uses
the movement-speed talent.

- 5,963 synthetic checks in 119 groups passed. Source and publication CI passed.
- Package checks covered both editions, tools, and components; current-client
  binding checked all 158 native read paths with bridge version 130.
- Original 1.4.16 helpers passed both editions' actual upgrade, failed-start
  rollback and persisted-interruption recovery: six cases.
- Native repair passed both editions with damaged descriptors, helpers and
  launcher/runtime files. Startup acknowledgements and all package bytes were
  checked before exact fixture-owned process disposal: two additional cases.
- The original 1.4.16 client reconstructed all 221 Lite / 677 Portable files from
  the public capable feed.
- Public repair replaced two deliberately missing/damaged files per edition,
  downloading 2,137,088 bytes each. Every target hash and the retained plugin
  sentinel were checked. This transport check did not launch the application;
  native acceptance separately covered replacement and startup.
- Seven public checks covered signatures, exact manifest bytes, CDN redirects,
  CDN/origin ranges, repair blocks, and unchanged older feeds.

These are release and updater checks, not a claim that every game task has been
played through. Persisted-interruption injection is not a physical power-loss test.

## Acceptance timing correction

An initial native-repair test read the startup journal immediately after the
application acknowledged the update. The acknowledgement precedes the subsequent
visible-window record, causing a test race. The script now waits up to 30 seconds
for the expected version's visible-window record and still requires the matching
process acknowledgement and every correct package byte. The failed fixture and
its later verified successful startup were retained; a fresh scripted run passed
both editions. No computer-use clicks or changes to application behavior were used.
