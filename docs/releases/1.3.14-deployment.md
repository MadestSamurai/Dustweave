Published on 2026-10-15 (Asia/Hong_Kong) as a normal [GitHub release](https://github.com/MadestSamurai/Dustweave/releases/tag/v1.3.14), with domestic layout-2 OTA live.

## Source and validation

- Tag `v1.3.14`: `8f924f534d4f31583221c9e0e108e0dbd43e0665`.
- Includes guarded recovery of vanished event confirmation windows, removal of the saffron pre-harvest tour, recovery of missed food callbacks, Pandora boss movement and combat decisions, and fair retention of recent diagnostic evidence. See [release notes](1.3.14.md).
- Full local regression: **4,420 checks in 97 groups**. The focused event preview, sweep count, trade boundary and diagnostic export run passed **176 checks**. Both packaged editions passed their UI, language, component and ownership checks. Installed-client compilation, all 11 observation configurations and the unified tool suite passed.
- [Source CI](https://github.com/MadestSamurai/Dustweave/actions/runs/38700275727) and the [release workflow](https://github.com/MadestSamurai/Dustweave/actions/runs/38702412290) passed. GitHub Actions verified the tag, candidate identity, package hashes and content boundary before publishing a normal release.
- The actual **1.3.13 updater** passed Lite/Portable differential upgrades, startup-failure rollback and interrupted-bootstrap recovery using synthetic fixtures. Installed file hashes and account/plugin preservation were checked. Interruption was injected; this is not a physical power-cut test.
- An initial packaging attempt encountered a transient file-access failure in the binding cache. The unchanged focused binding checks and subsequent full package checks passed. Failed-run evidence remains available; the precise cause of the transient access failure was not established.
- No game was connected or operated during this release. Offline checks use synthetic fixtures informed by diagnostics and installed game code; affected-user gameplay remains a separate verification step. Pandora simulation results are not live-game win rates.

## Event confirmation recovery

The reported failure showed that the event preview had disappeared after its quantity was read but before confirmation was submitted. The log does not establish why the game closed that preview. Both native auto-battle and sweep paths now re-read the current state at confirmation and can reopen an unsubmitted preview only if the same lobby, stage, account and AP balances remain valid. There are at most three opening attempts. Submitted or ambiguous actions are not replayed. A dedicated recovery record is exported, and recent records from each diagnostic category are retained before bulk history.
