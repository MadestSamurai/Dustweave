## Validation and limits

- The final canonical package ran the full local regression suite: **3,655 checks in 83 groups**. Its source inventory matches the tagged source. Evidence: `artifacts/tests-20261013-191528-1302` and `artifacts/package-1.3.3-6dde5e531ffc4d6db0e341f5962249ae`.
- Both Portable and Lite passed actual WPF smoke runs, 249 presentation checks, 79 support checks and 20 tool-session checks. Coverage includes three languages, both themes, minimum 920×650 windows, empty/error states, translated accessible names, keyboard tab stops, settings search and revealing hidden invalid fields without resetting input.
- Account management, scheduling, diagnostics, software preferences, onboarding, tools, plugins and updates were rendered and inspected. Updated documentation screenshots use fictional accounts.
- Startup registration uses an in-memory registry in tests: enable/disable, executable quoting, moved paths and independence from automatic daily execution. Closing choices persist. Corrupt preferences preserve their original file and prevent automatic execution. No actual Windows sign-in or physical keyboard/screen-reader test was performed.
- Sandbox repair fixtures cover automatic matching and manual correction while rejecting foreign-account candidates. No live game, injection, account binding, Windows startup registration or real scheduled task was performed for this UI task.
- An early packaged check failed because a preset fixture restored the closing preference on disk without refreshing its selector. The fixture now restores both. A later tool-switch probe used an artificial three-second close deadline; isolated observations showed normal WPF teardown taking about 4.9 seconds. The normal probe now uses the existing production 15-second deadline, while the intentional refusal case retains a separate short deadline. **Production tool-close timing was not changed.** Earlier failed candidates and observations remain available; the final canonical package reran all gates without reusing those candidates.
- Real updater acceptance used the original published **1.3.2** packages and helpers. Both editions upgraded through a delta; startup-failure rollback and interrupted-transaction recovery passed. All inventoried files and account/plugin preservation sentinels were checked. Interruptions were simulated with real process restarts, not a physical power cut. Evidence: `artifacts/build-1.3.3/acceptance-final-ui/results.json`.
