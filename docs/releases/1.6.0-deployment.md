## Upgrade behavior

The existing differential format and self-copy transaction remain in use. No new block reconstruction algorithm was introduced in this urgent release. The 1.5.17 bridge acknowledges its first transaction only after its progress window exists, then completes the pinned 1.6.0 update. Reopening resumes after cancellation or a delivery failure; target startup failure rolls back without repeatedly relaunching the failed target.

The bridge's Lite runtime prerequisite was corrected during actual acceptance: it uses .NET 8.0.0 and normal patch roll-forward, consistent with the released Lite host. Portable contains the pinned runtime. The failed initial fixture was retained; it rolled back instead of stranding the installation.

The final Lite archive also excludes a debug-symbol file emitted into a shared build output during bridge preparation. Only that file and its inventory entry were removed. All actual acceptance below used the final archive hashes, not the earlier packaging-stage ZIP.
