## Corrections

Weekly navigation now distinguishes combat enemies from capture targets and
breakable objects, checks the current map's native threat state before stealth,
and briefly re-reads an already cast talent's effect without casting or spending
again. Background maintenance yields to foreground work and no longer disables
the entire host. Historical internal caches follow the configured retention age;
active files, accounts and user-selected exports remain protected.

The 19:14 territory diagnostic exposed a separate shared interruption. At
16:23:45.332 local time, an expired three-second background owner observation
destructively paused the tool. At 16:23:45.508, the same PID and creation time
were confirmed alive, but the retired operation did not resume. A validated OS
process handle now retains the exact lifetime and uses a zero-time exit signal;
thread-pool delay no longer expires an otherwise living owner. Real exit,
replaced process lifetime and account changes still stop operations.

The host also treated a temporarily empty tool name during same-owner handoff
as a terminal session change. It now waits for that transition; another owner
or another ready tool is still rejected. These changes apply at shared tool
boundaries rather than to territory alone.

The same diagnostic shows a successful 1.5.0-to-1.5.3 update followed by startup
of 1.4.18 from a different installation directory. That user must replace the
old shortcut. The updater receipt does not indicate rollback. The final 19:14
stop follows a window-close event; not every recorded stop shares the runtime
failure above.
