# Dustweave 1.4.0

## 中文

本版集中改善日常结束后的反馈、账号隔离和内置工具使用体验，并修复特殊跑商。沿用 1.3 系列的目录结构和运行库，无需重新保存正常可用的账号。

### 日常结果与提醒

- 新增执行结果汇总：不重复罗列完全成功的普通环节，重点显示抽取结果、暂缓或未完成的事项，以及活动自动战斗失败后回退扫荡等情况。多账号执行按账号汇总。
- 在“软件设置”选择 Windows 通知、结果弹窗和声音，可组合使用。默认开启 Windows 通知与结果弹窗，声音默认关闭；提醒失败不影响执行结果或后续账号。
- 免费抽取显示五星服装和五星角色 UR 专武的获得数量，并可打开详情查看名称、稀有度和重复服装转换情况。旧记录未保存明细时不会猜测抽取结果。
- 周收集等地图详情优先显示“卡带名称 · 地图名称”；旧记录或暂缺名称数据时保留编号供排查。
- 统一任务详情、抽取详情与结果弹窗的背景、列表和深浅主题。
- 修复开启“日常完成后退出游戏”后，队列自然结束但含暂缓事项时没有退出的问题。暂停、主动停止、异常中断或仍待核对的队列不会触发自动退出；只关闭本次绑定的游戏进程。

### 藏红花与土豆等待

- 等待本轮土豆全部成熟期间，可以继续砍树、采矿。整轮成熟后结束当前资源采集动作并优先回田收割。
- 完成设定轮数的土豆种收后，继续收完剩余树木和矿物，再衔接后续流程。
- 保留既有的料理准备、藏红花收割与补种、加工售卖规则；不因为等待期间采集资源而额外使用增产料理。

### 账号与隔离启动

- 账号管理恢复单账号“隔离启动”：为选中账号打开独立的织尘窗口，适合希望分别控制两个日常的用户。首次使用显示用途说明，可勾选“今后不再提醒”。需要已安装 Sandboxie。
- 沙盒内日志、执行状态、组件缓存和更新缓存使用独立运行数据，避免继承主窗口旧日志或缓存配置。账号设置继续按现有机制提供，普通队列与隔离队列的行为不混用。
- Windows 重装等原因导致旧凭据无法解密时，用户重新登录同一账号、关闭游戏并保存，可修复原账号槽位，保留名称、顺序和日常设置。不会根据不可读取的旧凭据自动登录，也不会覆盖另一账号。

### 内置工具

- MANSION RUNAWAY 和装备助手打开后先显示实际工具窗口及加载动画，再准备连接；支持取消、关闭和失败后重试。
- 准备连接期间共用工具互斥，防止与日常或其他工具抢占控制；空闲窗口不持续占用执行权限。
- 调大装备助手“允许 5 药 N 装”选项的字体和点击区域。

### 更新缓存与特殊跑商

- 本地更新缓存最多保留 2 个版本、最长 7 天，超过任一限制即可清理；同一版本的 Lite 和 Portable 合计为一个版本。此规则不影响线上最近十版的差分更新覆盖。
- 清理已结束的旧安装副本和临时更新器；正在下载、安装或仍需恢复的记录受到保护。自动清理遵守用户开关并在空闲时执行，手动清理采用相同规则。
- 修复“只购买收藏”准备砍价时错误读取普通跑商 `execution.json` 而中断的问题，也覆盖购买后退出商店、收藏已购完及金币不足的收尾。旧计划缺失、损坏或失败记录不再阻挡新一轮执行。
- 特殊跑商仍先砍价，只购买用户收藏，不做料理或售卖；交易结果未确认时不会重复下单。

## English

This release improves completion feedback, account isolation and hosted-tool loading, and fixes favorites-only trade. It retains the 1.3 folder layout and runtime; working saved accounts do not need to be recreated.

### Results and notifications

- A completion report highlights draws, deferred or unfinished tasks and event-battle fallback sweeps. Routine successful stages are omitted; multi-account results are grouped by account.
- Choose Windows notifications, a result popup and sound in Software settings. Windows notifications and the popup are enabled by default; sound is off. Notification failures never change task results or block later accounts.
- Free-draw details show five-star costumes and five-star character UR exclusive equipment, with names, rarity and duplicate conversion information. Older records without reward details are not guessed.
- Map details prefer cartridge and map names, retaining identifiers when names are unavailable. Task, draw and result dialogs share consistent light/dark styling.
- The optional exit-game action now also handles naturally finished queues with deferred items. Paused, stopped, interrupted or unresolved queues keep the game open. Only the game process owned by that run can be closed.

### Saffron cycle

- Gather wood and ore while waiting for the entire potato round to mature. Once ready, finish the current gathering action and prioritize harvesting the fields.
- After the configured potato rounds, finish remaining wood and ore gathering. Existing food, saffron replanting, cooking and sale rules remain in place; waiting-time gathering does not consume extra buff food.

### Accounts and isolated launch

- Launch the selected account in a separate sandboxed Dustweave window, with an introductory explanation and a “Do not remind me again” option. Sandboxie is required.
- Isolate sandbox execution state, logs, component caches and update caches from the host's operational files.
- After a Windows reinstall invalidates saved credentials, sign in to the same account, close the game and save again to repair its original slot while retaining its name, order and task settings. Unreadable credentials cannot be used to sign in or overwrite another account.

### Tools, storage and trade

- MANSION RUNAWAY and Equipment Assistant show their windows and cancellable loading indicators before preparing a connection. Preparation shares the automation lock; idle windows release it. The 5-potion N-equipment option has a larger font and hit area.
- Update caches are limited to two versions and seven days. Finished temporary copies can be removed; active installations and unresolved recovery remain protected. Idle cleanup respects the automatic-cleanup setting. This does not reduce the publisher's ten-release patch window.
- Favorites-only trade no longer requires a normal optimizer history file when starting bargaining or leaving the shop. Missing or corrupt old plans do not block a fresh run. Empty favorites and insufficient funds also close correctly. Bargaining remains required; this mode neither cooks nor sells, and uncertain purchases are not repeated.
