# Dustweave 0.9.18

私有本地更新，未公开发布。

- 游戏服务协议（AgreementPopupUI）与登录失效分开处理。等待用户确认时撤销自动输入许可，暂停登录超时计算；确认后继续身份核对。用户可以随时停止。不会代替用户同意服务条款。
- 保存游戏实际写入的协议确认日期，跟随同账号加密快照交接；仅同客户端、目标记录缺失时原样恢复。已有记录不覆盖，旧快照不补造，客户端更新后不复用旧记录。协议变化不刷新令牌年龄。
- 保存同一登录令牌以及账号资料字段变化不再刷新凭据年龄；保存时保留更晚的真实令牌，观察基线仍记录实际读取的状态。
- 隔离游戏已经关闭自动登录时，不再重复导入相同凭据。只有已保存、更新且不同的登录凭据才能替换；正常账号身份、DPAPI 加密及进程隔离校验保留。
- 登录交接记录账号摘要、令牌单向摘要与选择结果，不记录令牌内容。

## 实机与离线边界

2026-10-09 10:16 的两个隔离实例均停在协议确认。用户确认后，两份游戏日志都记录了登录成功，未出现新的 InvalidAccessTokenException；这说明本次重开没有丢失令牌。此前 2026-10-08 的两份旧日志确有错误 120，与本次现象不能混为一谈。

等待协议后自动接续、取消、凭据时间与失效替换保护均经过定向回归。此次没有注销账号、清空沙箱或改写实际用户凭据；新版真实队列在协议确认后接续仍待实际使用验证。不得把本次登录成功外推为所有跨环境往返均已验证。

## English

Service-agreement waits are now separate from authentication failures. Dustweave retains the queue and resumes after the user confirms the agreement, without accepting terms on their behalf. Re-saving an unchanged credential no longer makes it newer; a disabled isolated login is replaced only with a genuinely newer, different saved credential. Diagnostic records contain one-way stamps, never tokens.

Both observed isolated games signed in after user confirmation. The old error-120 records belong to an earlier run. Previously confirmed agreement dates now travel with the encrypted account snapshot and restore only when absent, for the same account and client. Existing records are retained; old snapshots cannot invent acceptance. New queue-resume and repeated-restart behavior has synthetic coverage and awaits live use.
