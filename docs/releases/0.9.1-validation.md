# Dustweave 0.9.1 local acceptance / 本机验收

Date: 2026-10-07. Status: local release candidate, not committed, pushed or published in this change.

## Result / 结果

- Canonical `package.ps1` produced both flavors from one unchanged source snapshot: `artifacts/releases/0.9.1/release.json`. Build: `artifacts/package-0.9.1-f9cc5846a2a849e1ada240a2af9e6a0e`.
- Regression: 2,130 checks in 57 groups, `artifacts/tests-20261007-130756-4458/results.json`.
- Both packaged applications passed UI, integrated tool, utility identity and offline installed-client compatibility checks. Scheduling/update UI covers 43 checks per flavor, including both themes, all three languages, real modal acceptance/cancellation, dimming cleanup and custom chrome. Dark Chinese/light English dialog renders and dimmed owner renders were visually inspected.
- The territory smoke fixture now refreshes its synthetic observation before each start assertion. Its earlier stale-heartbeat failure was in the offline fixture; production heartbeat validation was not relaxed.

## Actual executable acceptance / 真实成品验收

1. `artifacts/ota-delta-0.9.1-check-r2/results.json`: the 0.9.1 update helper upgraded isolated Lite and Portable 0.9.0 installations using only delta packages, without cached full ZIPs. The installed EXE hashes exactly match the full packages; new app startup was acknowledged. Account/plugin sentinel files remained intact.
2. The same run rejected a deliberately incompatible patch, fell back to a cached signed full package, and restored the previous executable when that intentionally invalid executable could not start. It also recovered a persisted interrupted replacement through the actual app bootstrap.
3. `artifacts/ota-full-0.9.1-baseline-helper/results.json`: both complete upgrades passed using the actual **0.9.0 helper**, proving older clients can read the additive feed and install 0.9.1. Full-package startup failure and bootstrap recovery passed as well.
4. Isolated profiles suppress release notices for both tested versions, so restoration to the old app does not block the test harness in its old startup dialog. This changes only test profiles, not user settings or application behavior.

0.9.0 itself cannot apply deltas. It needs one complete upgrade to acquire the 0.9.1 client; later releases can use direct deltas. The test above intentionally uses the new helper to validate the patch engine. It does not claim that the old client has patch support.

## Boundaries / 边界

No game connection, component injection, gameplay, real scheduled task or production publishing occurred. The user's installed app and real account/plugin files were not replaced. Interruption was injected into an isolated transaction; this is not a physical power-cut test. Public HTTPS distribution of 0.9.1 remains a separate release step.

Packaged source remained stable during the successful build. Afterward only acceptance-script options and documentation were updated; no bundled executable or data source changed. Earlier failed/draft package directories remain diagnostic evidence and must not be distributed.

### Subsequent account-card edit / 后续账号卡片调整

Source build and full isolated WPF smoke pass; scheduling/update coverage is now 60 checks. Evidence: `artifacts/smoke-20261007-155756-9684/`. Light Chinese, dark English and the compact picker were visually inspected. No schedule or game command was issued. This UI change has **not been repackaged**; the earlier ZIPs in `artifacts/releases/0.9.1/` do not include it and must be rebuilt before publishing the revised version.
