## Fix and evidence

The reported weekly run opened quest 101351 in pack 13. `QuestPopupUI` appeared
after 0.42249 seconds but still contained prefab content and no native accept
context. Selection checked too early; recovery then required that same missing
accept context to close the detail popup, masking the original cause and stopping
the merged weekly tasks. No quest acceptance was dispatched in that incident.

The host now waits up to eight seconds for the selected native quest and its
accept eligibility, reopening the non-consuming detail view at most once. Back
closes quest details over a visible board without requiring initialized accept
metadata. The game's back handler closes the view without accepting or abandoning
a quest. Unrelated quest popups outside the board remain untouched. Original
recovery failures are recorded before cleanup. Account/process/cycle boundaries
and the single consuming accept operation remain unchanged.

## Scoped verification

Local packaging used **Weekly** scope and reused the completed 1.6.4 Full baseline
for unchanged client components. The 24 affected regression groups passed 1,784
checks. Fixtures cover delayed initialization, reopen success, persistent failure,
cancellation, cycle changes, unrelated popups, recovery after restart and no
duplicate acceptance. The merged-run fixture verifies that NPC failure does not
block independent collection/theft and that restored conditions can resume.

Both actual editions passed startup/UI and bundle integrity checks. Released
1.6.4 self-updaters passed upgrade, failed-target rollback, interruption recovery
through the host and preserved copy, and damaged-base refusal (ten cases).
Account/plugin sentinels were preserved. No live game was operated; synthetic
recovery tests do not establish live-game reliability.

Small fixes now explicitly reuse scoped validation in AGENTS.md. The scope mapper
ignores the worktree pointer and only normalizes the Accounts lock's empty RID
target when the resulting bytes match the previous recorded hash. Independently
deployed publisher-only changes receive their own 206-check executable self-test.
Unknown runtime changes were verified to reject Weekly scope. The existing remote
Build workflow ran once successfully for the final commit; it was not repeated
locally. Unfinished Claude tool UI changes in the main checkout were excluded.

The first remote run exposed an overly strict fixture expectation: that fixture
retains collectible items, so its valid independent result may be `partial`.
The assertion now permits completed/partial collection while still requiring
completed theft and deferred NPC work. The first publisher self-test encountered
a transient Windows directory-move denial; its unchanged isolated rerun and the
packaging run passed. Failed evidence is retained. A first publication attempt
also found the missing remote version tag; after pushing the exact verified tag,
only the publication workflow was rerun. No rebuilding or regression rerun was
needed for that metadata correction.
