# AIO delivery correction · 2026-11-04

## Incident and cause

All 16 signed 1.5.15 patches were uploaded, fully downloaded and SHA-256 verified.
The server enabled cloud delivery at 2026-11-03 23:59:50 +08:00. Public download
checks observed CDN redirects for all 16 patches. Later HEAD health checks failed
at 00:06:36 and 00:11:22; the old publisher removed a lane-wide enable file. This
diverted unrelated patch downloads to the origin. The timer recovered at 00:16:27,
but that recovery did not fix the recurrence risk.

Each HEAD had a six-second deadline and three attempts. A failure of any one
historical baseline disabled the whole lane. The old nginx `limit_rate 2m` was a
per-request rate, not an aggregate outbound budget. Clients could also explicitly
request origin bodies using `?origin=1`. Treating origin fallback as successful
delivery was therefore inconsistent with the server's bandwidth role.

The available evidence establishes probe cancellations and intermittent 503s. It
does not establish a storage-wide outage or identify which network hop timed out;
the old probe error omitted the file name. New cancellation records identify the
method, file and attempt.

## Corrected behavior

- AIO patch routes depend on a fully verified immutable per-file receipt, not the
  current health-probe result. Existing routes survive transient failures and a
  restart with the old disabled switch. Health reports `cdn-degraded` separately.
- No public AIO route serves local patch bodies. `?origin=1`, HEAD and Range still
  redirect to object storage. Missing routes return uncached 503/Retry-After;
  complete archives and internal receipt paths remain inaccessible.
- Cloud bodies are verified before switching the signed release index. Failed
  preparation leaves the previous index live and preserves resumable progress.
- Existing clients retain their bounded retry and SHA-256 checks. An unavailable
  cloud download can be retried later or replaced by manual GitHub/Quark download;
  it never turns this origin into the payload host. No client rebuild is needed.
- Only the AIO publisher and its marked nginx section change. Old updater/repair
  lanes, plugin delivery, accounts, signed feeds and immutable package files are
  not modified by this installation.

## Acceptance and deployment

Windows and Linux publisher suites each passed 186 checks. Real nginx passed 12
delivery checks including forced-origin and Range requests, a present local file
with no verified route, no health switch, and unchanged index/other paths. Four
disposable-container installation cases passed: success, nginx rejection with
rollback, invalid digest, and occupied publication lock. These are local checks,
not evidence of production installation.

Install with `scripts/upgrade-update-aio-delivery.sh`, supplying exact new and old
publisher digests and the live feed digest. It saves the previous executable and
bind-mounted nginx configuration, changes only the marked AIO section, validates
nginx before reload, respects the publication lock and checks unchanged feeds.
On failure it restores both executable and configuration. The existing restricted
transport cannot update its own executable or nginx; administrator installation
is required as documented in `../OTA_PUBLISH_CHANNEL.md`.

After installation verify the signed feed unchanged, current Lite and Portable
redirects with and without `?origin=1`, CDN range responses and hashes, status
showing `originFallback=false`, and the retained restricted transport. Revoke the
temporary administrator key after verification. Deployment evidence belongs in
`artifacts/deployments/aio-cdn-only-20261104/`.
