## Delivered behavior and validation

Supported old clients approve once, install the internal `1.4.15-bridge.1`, then
automatically reach final 1.4.15. The bridge does not connect to the game, run
daily automation or execute schedules. The final native entry and self-contained
helper permit launcher/runtime replacement, signed reconstruction of damaged
installations, interrupted replacement recovery and startup-failure rollback.

- Local full baseline: 5,784 checks / 118 groups; final affected checks: 429 / 11
  groups. Release CI passed 5,780 checks. Conditional host checks can differ.
- The publisher passed 136 checks on Windows and on the production Linux host.
- Actual original 1.4.7 and 1.4.14 helpers passed both editions of the two-stage
  upgrade, with every target file verified. Separate checks cover rollback,
  interruption before/after native entry replacement and native repair with broken
  startup files, helpers, descriptors and Portable runtime.
- Public original 1.4.7 and 1.4.14 client binaries resumed downloads at byte 65,536
  and reconstructed all 221 Lite / 677 Portable bridge files from the actual URLs.
- The actual bridge client downloaded and prepared final 1.4.15 from the live
  capable index, verifying all 221 / 677 target files.
- Public signed repair detected a damaged business assembly and a missing launcher
  assembly in each isolated edition. Only 2,137,088 bytes per edition were needed
  to prepare valid replacements; all target files and the plugin sentinel passed.
  This public check prepared repair data; replacement/startup were covered by the
  packaged native acceptance, not repeated against a user's installation.
- Both GitHub full downloads matched the original hashes. Twenty-eight public
  checks covered signed indexes, all patch redirects and CDN/origin byte ranges,
  exact repair envelopes and sampled helper blocks. The delivery state stays hidden.
- No game or real account automation was operated. Process interruption tests are
  not physical power-loss tests.
