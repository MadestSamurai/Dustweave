# Dustweave 1.3.15 delivery

Published on 2026-10-15 (Asia/Hong_Kong) as a normal [GitHub release](https://github.com/MadestSamurai/Dustweave/releases/tag/v1.3.15), with domestic layout-2 OTA live.

## Source and validation

- Tag `v1.3.15`: `e506e4c01dd75f2d19858273f456e824dfda710e`. See [release notes](1.3.15.md) for the integrated Equipment Assistant, legacy log maintenance, current event-cartridge mapping and dark-theme changes.
- Full synthetic regression: **4,460 checks in 97 groups**. Focused log cleanup and diagnostic export: **81 checks**. Packaged native command scope, expiry and screen validation: **606 checks**. Both editions passed their packaged UI and component checks; all 11 installed-client observation configurations and the unified suite's 15 components passed.
- The first full package run passed the synthetic suite, then caught an outdated native self-test expecting a hidden event cartridge to be available. After correcting that fixture, packaging reused the successful synthetic result only after confirming that `src/Connection/SelfTest.cs` was the sole changed runtime-tree input and was outside that synthetic suite's inputs. Builds, native checks, packaged UI and component checks ran again. Provenance explicitly records this reuse; failed and interrupted run evidence remains available.
- [Source CI](https://github.com/MadestSamurai/Dustweave/actions/runs/38722210930) and the [release workflow](https://github.com/MadestSamurai/Dustweave/actions/runs/38724798403) passed. GitHub Actions checked the source tag, package identities, hashes and distribution boundary before publishing.
- The actual **1.3.14 updater** passed Lite/Portable differential upgrades, startup-failure rollback and interrupted-bootstrap recovery. Installed file hashes were checked. Tests used isolated data, did not register scheduled tasks and did not touch the game. Interruption was injected, not a physical power cut.
- No game was connected or operated. Installed-client compilation and offline UI checks do not establish live gameplay behavior. A warm configuration-preparation benchmark improved from about 18.46 seconds to 0.40–0.44 seconds; this is not a measurement of the complete live inventory read.

## Legacy equipment logs

Idle maintenance imports only recognized old equipment diagnostic files into Dustweave diagnostics, retaining their original timestamps. Normal retention then expires them, and empty allowlisted legacy log folders are removed. Pending batches, inventory, IPC and connection state remain in their existing data locations. Locked files, links and unknown files are skipped. Migration is not on the equipment inventory-read path. Automatic maintenance follows the host cleanup setting; manual cleanup also imports these logs.
