# Dustweave 1.2.6 本地验证 / Local validation

修复 1.2.5 更新连接组件后，旧步行拾取记录仍然阻塞周收集的恢复缺口。

旧记录保留原连接的完整请求和成功回复，却缺少后来新增的物品可拾取字段。此前恢复把新连接身份和旧操作身份混为一谈，并要求已经结束的旧操作重新提供新版字段；因此主菜单接续立即停止，新计划则在切图、使用探查后再次被同一记录阻塞。

- 将历史步行记录退出待核对，与当前寻路重试分开判断。完整旧回执按原身份校验；当前账号、角色及服务器必须匹配。不会重放旧输入，也不会将原目标记为已收集。
- 新计划、接续、补跑统一在导航前检查未确认操作；真正缺少回执时仅保留相关环节的阻塞，不重发请求。
- 同一游戏进程的观察组件更新允许接续原队列，原进度保留；业务记录仍单独核对，不跳过身份和周期检查。

验证覆盖旧观察字段、连接实例变化、主菜单／地图、三个启动入口、缺失回执、不同账号／服务器，以及恢复后用当前目标实例完成拾取。用户原始日志仅在私有目录离线重放，不进入源码或软件包。真实用户地图仍需复测。

本包复用 1.2.5 已通过的完整客户端及独立工具验证；重新编译主程序，运行队列、业务与周收集相关回归以及两种成品启动检查。塔防位置优化不在本包内；此文不表示 GitHub 或 OTA 已发布。

This local build separates completed historical navigation from active movement retries, reconciles all queue entry points before travel, and preserves interrupted queues across observer reloads in the same game process. Historical responses retain their original identity; no old input is replayed and no target is assumed collected. Private archive replay and synthetic regressions are distinct from pending live-user verification. Unchanged client/tool checks reuse the complete 1.2.5 baseline; host and package checks run again.
