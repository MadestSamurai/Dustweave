# Talent practice / 技能练习

## Optional periodic restart · 1.7.3

The interval dropdown is off by default, or every 15/30/60/120 minutes. It saves per account and may be changed while running; changing it starts a fresh interval. The timer uses monotonic time and checks only between settled skills. An unfinished transaction follows its existing reconciliation path before restart. The queue and counters survive the handoff; current game XP and achievements decide what remains.

Normal window close and the existing desktop/Sandboxie launch route restart the exact executable in the same scope. No account slot is activated and no credentials are restored or rewritten. A single pinned Touch to Start permit cannot approve downloads or a second login. Stop cancels the handoff; a close, launch, login or identity failure preserves progress and pauses without looping. The shared tool and controller locks remain held across the handoff. Synthetic `PracticeRestart` checks cover clock changes, settlement deferral, normal restart, missing observations, cancellation, identity changes, failed close and repeated-login refusal; `bargain` UI smoke checks the dropdown in all languages/themes. Offline checks do not establish real weak-network reliability.

## Queue and achievement goals

XP queue entries retain the talent level selected when added. Refresh removes entries whose confirmed level changed, including completed entries, saves the remaining queue and recalculates its pill estimate. Missing observations and same-level XP changes do not remove anything. Older saved queues adopt their first known level, or compare with the previous live snapshot if available. Running without refreshing also skips a changed tier before spending. Achievement goals remain skill-wide and are not removed when a costume levels up.

刷新进度时，技能等级已变化的服装会自动从练习列表移除，并提示移除项目、重算剩余耗药。若要练习新等级，请重新加入。等级未变而经验增加、暂时未读到服装，不会导致移除；成就次数任务不受服装升级影响。

The tool has two goals: **Talent experience** trains the selected costume to the current tier cap; **Achievement uses** selects the owned costume with the lowest current pill cost and continues until the game's highest use-count achievement is complete, including after XP is capped. Add entries to the practice queue, reorder or remove them, then run the queue. Queues are saved separately for each account; restarting retains completed entries and refreshes pending work against live game progress. A capped XP entry is complete and does not prevent later entries. After upgrading with a book, add that costume again to train the next tier.

**天赋经验**模式选择服装练满当前等级；**成就次数**模式选择技能，由工具自动选择单次耗药最少的已持有服装，刷到游戏成就的最高档。两种任务可以混合加入列表、排序和移除。同类技能保留列表顺序；药量足够时，不同野外技能会在同一张图内依次练习，需要重置效果后再切图。列表按账号保存，暂停后再次运行会读取游戏最新进度，只继续未完成项。成就模式不要求一次备齐全部药，药不足时保留进度，不自动购买。

Achievement targets come from all permanent `AchievementTable` skill-use rows (`ConditionType=23`), grouped by skill/group/contents, rather than the currently displayed claim tier. The November 11 table's supported Bargain, Search, Danger Detection, Rush and Stealth chains end at 4,500 uses; 500 is intermediate. Swiftness currently has no such achievement. This number is evidence, not a hard-coded runtime limit. Login-loaded `AchievementDBInfo.Value` supplies cumulative progress, with cleared-tier thresholds as a lower bound. Missing observations never become zero. Only immutable definitions are cached; account progress is fresh on every capture.

Achievement mode keeps the normal skill submission and settlement path. A delayed achievement counter is observed for up to 10 seconds after the confirmed cast; no increase pauses further spending and remains resumable after refresh. XP-cap/no-growth stopping applies only to experience mode. Queue metadata stores goal type and character identity, not stale counters or a permanently chosen achievement costume. Unknown consuming outcomes stop further commands until existing recovery reconciles them. Insufficient resources found before an entry leave it retryable while other affordable independent entries can run.

Field practice uses the normal cartridge switch and the game's minimap quick travel. It never calls force-reset functions, changes XP, suppresses monsters or walks through combat maps. Outdoor safety is read from explicit native travel metadata: the generic proto view omits default-valued fields such as `mapType=0`. Interior shops/inns are not training destinations. The chosen talent row must still belong to the selected character and skill group immediately before clicking. Each successful round records actual XP and medicine consumption; no growth stops the run. Lost responses can be reconciled from fresh authoritative progress or a genuine game restart without replaying the old command.

Field-practice travel has one bounded 180-second loading window spanning command observation, temporary identity refresh, cartridge arrival and any quick-travel landing in the safe area. Nested waits share the remaining time; a ready map proceeds immediately. The ordinary daily-route defaults and public method signatures remain unchanged. A long load does not resend entry or cast a talent before the destination is ready. Stop remains available during non-consuming loading, while an already-submitted skill still settles normally. Timeout preserves XP; continuing after arrival adopts the current Chapter 1/2 safe area instead of needlessly returning to Chapter 1. Starting from the main menu still enters normally without requiring unloaded field data.

Field queues now batch independent skill kinds per map. The game's research/duration flags are skill-wide, not character-wide: another character of the same kind cannot bypass an active effect. Within a contiguous field-practice block, the first unfinished entry of each kind is eligible; achievements retain their position relative to XP training of the same kind. The scheduler uses fresh active flags and remembers used kinds until a normal cartridge switch. When the block's projected budget is not fully funded or is unknown, original queue priority takes precedence over interleaving. Bargaining remains a separate sequential boundary. One-round progress must actually advance; repeated ineffective rounds cannot reset the retry limit forever. Reconciliation of old journals is reused only within the same successful field trainer and invalidated on failure, avoiding a full historical scan on every cast.
