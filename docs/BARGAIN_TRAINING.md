# Talent practice / 技能练习

Open **Tools → Talent practice** with the selected account logged in. Select Bargain, Search, Rush, Swiftness, Danger Detection or Stealth, then an owned character. The window reads current-tier XP, talent-pill balance and estimated cost. Bargaining travels to the plaza merchant; the other five skills alternate between the outdoor safe areas of Chapters 1 and 2. Both chapters must be unlocked. The tool never buys pills or uses talent books. If the balance is insufficient for the tier, the window shows the shortage before training can start. At the cap it stops and asks the user to upgrade with a talent book, then choose **Refresh progress** to continue. The former trading-settings entry has been removed.

在已登录所选账号的情况下，进入**工具 → 技能练习**，选择砍价、探查、飞奔、疾速、危险侦测或隐身（繁中「藏身」），再选择角色、检查预计耗药后开始。砍价前往广场商人，其他五类技能在第一、二章的室外安全区之间切换，需先解锁两章。练满本级后停止，使用天赋书升级后可点击「刷新进度」继续。天赋药不足时先显示缺口；本功能不自动补药。日常队列的保药设置不作用于此手动工具，训练消耗以窗口显示的预算为上限。跑商设置里的旧入口已移除。

The idle dialog holds no controller lease. Reading and training use the shared daily module and control lock. The native skill definition supplies XP and cost; estimates round up the final partial attempt. Every consuming attempt must agree with the response, character XP and resource deltas. Failed bargains that grant XP count normally. Zero XP, changed identity/tier/cost or an uncertain result stop the run. Stop/close cancels an uncommitted preview or waits for the submitted round to settle.

After a round the native discount cancellation closes the shop but can retain its cached discount flag. The training loop checks its own exit instead of opening and closing an ordinary shop to refresh that flag. It then returns directly to the merchant talent menu, waiting on native readiness instead of a fixed post-round delay. Purchase pricing continues to require a fresh shop response.

Field practice uses the normal cartridge switch and the game's minimap quick travel. It never calls force-reset functions, changes XP, suppresses monsters or walks through combat maps. Outdoor safety is read from explicit native travel metadata: the generic proto view omits default-valued fields such as `mapType=0`. Interior shops/inns are not training destinations. The chosen talent row must still belong to the selected character and skill group immediately before clicking. Each successful round records actual XP and medicine consumption; no growth stops the run. Lost responses can be reconciled from fresh authoritative progress or a genuine game restart without replaying the old command.

Validation: `test.ps1 -Groups TalentPractice,BargainTraining,FieldTalent,CollectionReadiness,LocalizationArchitecture,UserText`; desktop smoke scopes `bargain` and `localization`. These use synthetic state and isolated UI data, and do not establish real-game throughput. The explicitly authorized `--utility talent-practice-check <output> <character> <rounds>` entry uses the same session/workflow and currently open account, limits runs to 20 casts, and saves before/after XP and consumption. Zero rounds is read-only. Training errors are included under `tools/bargain-training/logs` in the diagnostic export; consuming attempts use the existing managed business journal.

2026-11-10 live verification on the already-open account: 28 casts, 200 Talent Pills total. Gray / Detect traps: 0→17 XP over 17 casts (85 pills), stopped automatically at the tier cap; Rafina / Detect traps: 1→4 over 3 casts (15 pills); Liatris / Sprint: 26→34 over 4 casts (20 pills); Rubia / Dash: 184→196 over 4 casts (80 pills). Every run changed only its selected character's XP; talent levels were unchanged. Normal repeated cycles averaged about 12–15 seconds on this machine after initial preparation, with the first Gray sample averaging 21 seconds. Search is implemented and covered by synthetic workflow tests, but all owned Search characters were already at maximum level, so no live XP-growth claim is made for Search. Evidence: ignored `artifacts/talent-live-20261110/summary.json` and its per-run before/progress/result files.

Game names are not UI translations: character names follow CharTable.CharNameTextId; talent titles follow TalentTable.TalentNameTextId. The native reader supplies NameTextTable.TextCn/TextTw/TextEn from the running client. The window selects the matching interface language, and language switching preserves the selected character and skill. Only immutable name definitions are cached for the component lifetime; ownership, XP, cost and active effects remain live. Missing display names fall back to a readable game name or numeric identifier without becoming a training gate.
