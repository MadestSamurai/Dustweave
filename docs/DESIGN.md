# Dustweave desktop interface

Updated: 2026-10-20. The interface is a WPF desktop workspace for players watching multi-account tasks beside the game. Preserve the timeline, restrained green accent and light/dark/system themes. Source: `src/Desktop/App.xaml`, `DailyTheme.cs`, `Timeline.xaml` and the page views.

## Shared rules

- Use the existing Segoe UI family with system CJK fallback. Body text is 14 DIP, secondary descriptions 12–13, section and run-summary titles 20, and the main page heading 24. Primary actions and titles use semibold; secondary buttons use normal weight.
- Use theme resources for all surfaces, text and states. Keep content opaque, avoid decorative motion, and preserve the existing system high-contrast fallback.
- Fields and buttons normally have a 36 DIP minimum height; use an 8 DIP radius for buttons and text fields, and 6 DIP for selectors. Focus must not change border thickness or move content. Text editing, dropdown scrolling, selected items and keyboard focus are part of a control's behavior, not optional decoration.
- Main content and its header share a 24 DIP outer inset. Forms, tools and diagnostic content share the open page canvas; avoid placing a page-sized card around another set of cards. Related account controls retain a compact sign-in card and a distinct list surface. The dense account table uses 12 DIP vertical padding to retain useful rows at the 920 × 650 DIP minimum window size.
- Leave room for translated labels. Wrap toolbars when needed; trim long table values with a full-value tooltip. Scrolling belongs to the content region, leaving primary actions reachable.

- Let headings, controls and current values explain the obvious. Omit page introductions that restate the heading, default-value reminders next to visible values, and task summaries that only repeat a task name.

- Keep implementation history out of permanent help text. Put recovery instructions in the relevant state and retain original diagnostic evidence separately from localized presentation.
- Change Simplified Chinese, Traditional Chinese and English together. Prefer stable localization keys when editing existing copy; retain exact translations for messages still emitted by Core. Never translate arbitrary names, paths or protocol values.

## Sandbox installation guidance

- Preflight the whole parallel queue before account switches or worker creation. Account-page runs, run-on-open and scheduled parallel runs share the installation editor. Binding repair also checks this prerequisite. Ordinary single-account and sequential starts do not require Sandboxie.
- An interactive start offers the official Sandboxie-Plus download, an installed-folder picker, automatic discovery and explicit check-and-continue. Downloading or selecting a folder alone does not authorize execution; cancel preserves the queue and saved account identities.
- A missing prerequisite at a scheduled occurrence records that occurrence as failed and opens one non-blocking help window, before stopping tools. The ten-second scheduler does not retry that occurrence. Setup does not replay the missed schedule; the user starts manually or waits for the next occurrence. Repeated requests reuse the existing window.
- Passive detection and opening App settings never produce an installation popup. A missing location exposes Installation help beside Change location. Parallel execution settings and the schedule's parallel section offer the same editor. An invalid saved location stays visible and editable instead of silently switching installations.
- Use the shared dialog chrome, theme resources, accessible controls and three languages. Display a copyable official URL if the user's browser cannot open.
