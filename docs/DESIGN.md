# Dustweave desktop interface

Updated: 2026-10-14. The interface is a WPF desktop workspace for players watching multi-account tasks beside the game. Preserve the timeline, restrained green accent and light/dark/system themes. Source: `src/Desktop/App.xaml`, `DailyTheme.cs`, `Timeline.xaml` and the page views.

## Shared rules

- Use the existing Segoe UI family with system CJK fallback. Body text is 14 DIP, secondary descriptions 12–13, section and run-summary titles 20, and the main page heading 24. Primary actions and titles use semibold; secondary buttons use normal weight.
- Use theme resources for all surfaces, text and states. Keep content opaque, avoid decorative motion, and preserve the existing system high-contrast fallback.
- Fields and buttons normally have a 36 DIP minimum height; use an 8 DIP radius for buttons and text fields, and 6 DIP for selectors. Focus must not change border thickness or move content. Text editing, dropdown scrolling, selected items and keyboard focus are part of a control's behavior, not optional decoration.
- Main content and its header share a 24 DIP outer inset. Forms, tools and diagnostic content share the open page canvas; avoid placing a page-sized card around another set of cards. Related account controls retain a compact sign-in card and a distinct list surface. The dense account table uses 12 DIP vertical padding to retain useful rows at the 920 × 650 DIP minimum window size.
- Leave room for translated labels. Wrap toolbars when needed; trim long table values with a full-value tooltip. Scrolling belongs to the content region, leaving primary actions reachable.

## Pages

- **Navigation:** pair each destination with a shared vector symbol and show its localized name in the page header. Keep the page header for the title, connection status, Getting started and connection action. Application preferences live at the bottom of the sidebar. Display the current account beside an active or historical run; in a ready plan the account selector already identifies it. Green selection belongs only to the navigation icon and label; page content inherits the normal text color.
- **Window controls:** the main window uses WPF WindowChrome instead of a separate Windows title bar. Three 42 × 36 DIP controls align with the connection action at the right of the existing header; quiet line icons use the shared palette, with a soft red close hover and visible keyboard focus. The header stays draggable, while header buttons are client hit targets. Retain native resize/caption behavior, restore geometry and the existing close cleanup. Maximized content is inset using the current monitor work area and physical client bounds, converted through the current DPI; do not hard-code primary-screen dimensions or frame widths. Labels and restore state are localized. Application-owned release notes, confirmations, account editing, task details and trade windows share a themed custom header and close button. Modal dialogs dim the owner, restore prior focus after closing, accept Escape, and block scheduled starts while open. Native file pickers and emergency startup reporting retain system UI. Startup notes wait for the main window's first render.
- **Timeline:** show the run state, explanatory message, actual completion count and circular percentage in a compact summary above an open timeline. Group plan/history and selection controls in one wrapping toolbar. Use row separators, filled completion markers and a soft full-row highlight for the active task. Keep planned labels normal weight and emphasize only the running task. Distinguish the selected plan/history view from unavailable actions. Planned rows show the task and checkbox without repeating generic pending explanations. Use the shared 16-unit, rounded-stroke vector icons in `Icons.xaml`: task symbols before execution, explicit check/play/skip/pause/warning symbols during execution. Render right-aligned state labels directly on the row without a separate badge or background. Keep state text and accessible names; meaning must not depend on color alone. Actual run/history rows retain meaningful details. More detailed records are a secondary disclosure.
- **Progress and times:** the 68 DIP ring replaces the linear progress bar while retaining the native accessible progress range. Its center shows the completed/skipped stage percentage; round down and show 100% only when all stages have ended. Unstarted plans retain the task icon. Completed/skipped rows show their recorded `finished` UTC ticks as local `HH:mm` beside the status, with the full local date, seconds and offset in a localized tooltip. Missing or invalid timestamps stay blank; running retries never display a previous completion time. Carried results keep the original timestamp. No wall-clock estimate or game command is needed.
- **Daily settings:** keep account and Save visible; group task settings by purpose, with search across categories. Keep inputs on a common left baseline and use a consistent field column. Task options are collapsed until requested; expanding never changes the enable checkbox. Invalid values reveal their section and retain the entered text.
- **Trading settings and preview:** edit gold reserves, spending limits and the optional break-even resale strategy directly within the account's Trading section in Daily settings. Save with the other account preferences. Opening the plan preview saves valid edits first; the preview shows a read-only settings summary, refreshes settings on each calculation, and never writes preferences. Preserve existing ingredient reserves and distinguish a blank spending limit from zero.
- **Accounts:** separate the current local sign-in card from the saved-account list. The card identifies the current account, explains why session actions are unavailable while the game/launcher runs, and groups save/update, add-account sign-in and recovery. Each account row has its own game-entry action; it targets that row independently of the highlighted row or daily-queue checkboxes. Checkboxes define the daily queue, while highlighting chooses a rename/reorder/remove target. Do not expose batch sign-in verification or standalone isolated launch; queue execution mode explains sequential versus sandbox parallel runs. Filtered select-all changes only visible valid accounts and preserves hidden selections. Show empty/search-empty states and disable unavailable management actions. Retain three full rows at the minimum window size and a visible stop action during operations. The data-location note remains in the account count tooltip. Sandbox repair belongs to the highlighted account: show a uniquely verified candidate first, with Not this one revealing manual selection.
- **Appearance:** system/light/dark are three directly selectable segments with screen/sun/moon symbols, visible labels, selected borders and keyboard focus. Keep selection indices and preference persistence stable. The language selector remains a dropdown.
- **Timeline rail:** draw its full height in the item container, behind the node and content. The keyboard focus border is a separate overlay; its inset must never shorten the rail. Negative margins inside a data template do not reliably bridge container boundaries at fractional DPI.
- **Diagnostics:** show current connection status, a concrete next step and problem-report export. Do not display historical operation dumps, guild experiments, timeline shortcuts or disk management. Refresh uses existing read-only observations and waits for the read to finish. Reports and task errors remain distinct; status summaries exclude account identifiers.
- **Tools:** use the same page padding, control geometry and theme resources. Do not reserve a second footer-sized gap inside sidebar navigation. Scrollbar tracks retain their native available hit area, with a narrow visual thumb that highlights on hover/drag.

## Visual alignment

The timeline-led layout uses cool neutral backgrounds, blue-gray dark surfaces and a restrained mint accent. Summary cards carry the immediate state; the timeline stays on the page canvas, with uninterrupted rails in the item container. Keep component geometry and text contrast consistent across themes. Stable builds display the plain version number; the isolated interactive demo is still explicitly labeled as a design preview.

## Interface copy

- Let headings, controls and current values explain the obvious. Omit page introductions that restate the heading, default-value reminders next to visible values, and task summaries that only repeat a task name.
- Use one short description for the decision the user needs to make. Keep account scope, spending limits, prerequisites and the difference between resuming and rerunning explicit. Do not replace actionable errors with generic reassurance.
- Keep implementation history out of permanent help text. Put recovery instructions in the relevant state and retain original diagnostic evidence separately from localized presentation.
- Change Simplified Chinese, Traditional Chinese and English together. Prefer stable localization keys when editing existing copy; retain exact translations for messages still emitted by Core. Never translate arbitrary names, paths or protocol values.
- Compare actual WPF renders against the previous build in both themes and at compact widths. A reduction in copy length is not evidence of better task completion without user testing. See [the 2026-10-11 comparison](UI_COPY_ABLATION_2026-10-11.md).

### Schedule account selection

Scheduling has one daily local start time and a separate enable control. Do not show weekday choices. Keep next-run status, ordered account cards and Save schedule. The desktop clock and Windows daily trigger must agree; legacy weekday schedules are migrated with the original enabled state and identities preserved.

Show the selected schedule identities as compact cards directly on the page canvas, with execution order, alias, masked identity and a named remove action. Use a matching dashed Add accounts tile. Its searchable multi-select dialog excludes accounts already added, preserves checked choices across filtering, and changes the draft only on confirmation. Keep native buttons/checkboxes, visible keyboard focus, themed custom dialog chrome and all three languages. Preserve draft identity/order across catalog refresh; unavailable saved identities must stay explicit until removed. Empty selection teaches the add action, or directs users to save an account first.

### Parallel account overview

Reuse the timeline's circular percentage indicator. Account rows show the current state, completion time and explicit game/pause/continue/stop controls; detailed stages expand in place. Do not create one host GUI per automatically scheduled account. Execution mode sits beside the account queue action, with opt-in concurrent mode and a default capacity of two. State and error text use the same three-language dictionary; paused workers keep their occupied place.

## Application settings and scheduling

App settings owns appearance, language, Windows startup, run-on-open, closing behavior, installation locations, updates and log retention. Windows startup is an independent, per-user opt-in. A shared setting must not silently change task selection. Paths are concise rows that open focused editors. Errors are local and actionable.

Schedules is one plan, with sections separated by spacing and rules rather than independent cards. Keep the save action visible beneath the scroll region. The next occurrence is explicitly the saved plan; edits show an unsaved notice. Keep account-card ordering and the existing execution guards.
